# **Функциональные требования к MVP чат-бота банка**

## **1\. Гипотеза 1\. Постоянная возможность перехода к оператору**

**Цель:** предоставить пользователю возможность в любой момент перейти к оператору, одновременно информируя его о примерном времени ожидания.

| ID | Функциональное требование |
| ----- | ----- |
| FR-01 | Система должна отображать кнопку «Связаться с оператором» на протяжении всего диалога с чат-ботом. |
| FR-02 | При нажатии на кнопку система должна отображать предупреждение о возможном времени ожидания оператора. |
| FR-03 | Система должна предоставлять пользователю возможность подтвердить переход к оператору или вернуться к общению с ботом. |
| FR-04 | При подтверждении перехода система должна инициировать переключение на оператора. |
| FR-05 | При отказе от перехода система должна возвращать пользователя к текущему диалогу с ботом. |

## **2\. Гипотеза 2\. Объяснение возможностей чат-бота и выбор категории**

**Цель:** помочь пользователю быстрее понять возможности чат-бота и выбрать подходящий сценарий обращения.

| ID | Функциональное требование |
| ----- | ----- |
| FR-06 | При открытии чата система должна отображать краткое описание возможностей чат-бота. |
| FR-07 | Система должна отображать список доступных категорий обращений. |
| FR-08 | Система должна предоставлять пользователю возможность выбрать категорию обращения. |
| FR-09 | После выбора категории система должна отображать соответствующие варианты вопросов. |
| FR-10 | Система должна предоставлять пользователю возможность выбрать интересующий вопрос. |
| FR-11 | После выбора вопроса система должна предоставлять соответствующий ответ. |
| FR-12 | Если пользователь не находит подходящую категорию или вопрос, система должна предлагать альтернативные способы продолжения диалога. |
| FR-13 | Система должна предоставлять возможность вернуться к списку категорий. |

## **3\. Гипотеза 3\. Поиск по ключевым словам**

**Цель:** упростить поиск нужной информации за счёт возможности ввода ключевых слов вместо самостоятельного поиска по категориям.

| ID | Функциональное требование |
| ----- | ----- |
| FR-14 | Система должна предоставлять пользователю возможность искать информацию по ключевым словам. |
| FR-15 | Система должна отображать поле для ввода поискового запроса. |
| FR-16 | Система должна предоставлять возможность отправить введённый запрос. |
| FR-17 | Система должна обрабатывать поисковый запрос и искать соответствующие ему варианты обращений. |
| FR-18 | При наличии совпадений система должна отображать список найденных вариантов. |
| FR-19 | Система должна предоставлять пользователю возможность выбрать один из найденных вариантов. |
| FR-20 | После выбора варианта система должна предоставлять соответствующий ответ. |
| FR-21 | Если по запросу не найдено совпадений, система должна уведомлять об этом пользователя. |
| FR-22 | Если найденные варианты не подходят пользователю, система должна предлагать альтернативные способы продолжения диалога. |
| FR-23 | Система должна предоставлять возможность изменить поисковый запрос и выполнить поиск повторно. |

## **4\. Общие функциональные требования**

| ID | Функциональное требование |
| ----- | ----- |
| FR-24 | Система должна предоставлять пользователю возможность завершить диалог. |
| FR-25 | Система должна предоставлять пользователю возможность перейти к оператору в качестве альтернативы общению с чат-ботом. |
| FR-26 | Система не должна ограничивать возможность выбора альтернативного способа обращения. |
